Mixin expressions are line-oriented compile-time programs. They inspect Roslyn symbols and
attribute values, validate attribute usage, and emit C# into generated mixin targets. They run
inside the HELIX source generator; they are not runtime C# and cannot execute arbitrary
application code.

Expressions are normally attached to <FREntitySymbolLink uid="MixinExpressionAttribute" />.
Assembly-level <FREntityCodeLink uid="MixinPrepareGlobalAttribute" /> programs define shared
functions and variables used by several attributes.

## Program structure

Each non-empty line contains one directive:

```mixin
@DIRECTIVE<argument><argument> optional operand
```

Directive names are case-insensitive. Arguments use angle brackets and can nest. Whitespace after
the arguments separates them from the operand. There is no general comment syntax; blank lines
are ignored.

String operands interpolate references beginning with `@`. Write `@@` for a literal `@`.
Parenthesized arguments are evaluated dynamically rather than treated as literal strings.

```mixin
@CODE @this:name
@CODE email@@example.test
@MIXIN<(@local#Target)><(@attr#order)> Invoke();
@LOCAL<Field> _@(target:name)Ticker
```

The final two forms show the two uses of parentheses: evaluating a directive argument and
delimiting a reference embedded in adjacent text.

## Small complete program

```mixin
@ASSERT @this:?partial
@ASSERT @target:type:?class

@LOCAL<FieldName> @target:name
@LOCAL<Hook> _@(target:name)Subscription

@USING System;
@CODE<CLASS> private IDisposable @local#Hook;

@SCOPE<Qualified>
  @MATCH @attr#qualifier:!?eq<null>
  @MIXIN<$Init><(@attr#order)> @local#Hook = Subscribe<@target:type>(@attr#qualifier, @local#FieldName);
  @GOTO<Cleanup>
@SCOPE<Default>
  @MIXIN<$Init><(@attr#order)> @local#Hook = Subscribe<@target:type>(@local#FieldName);
@END

@SCOPE<Cleanup>
  @MIXIN<$Dispose><(@attr#order)> @local#Hook?.Dispose();
@END
```

The program validates its use site, derives generated identifiers, emits a class field, chooses
one initialization branch, and contributes cleanup to another lifecycle target. Output and
variable changes are committed only if the entire expression succeeds.

## Where expressions participate in generation

The generator collects mixin expressions from applied attributes, interface mixins, implicit
member attributes, and prepared assembly globals. It evaluates them against the annotated symbol,
then merges successful outputs with ordinary mixin method contributions. Ordering happens per
generated target; expression line order alone does not override a contribution priority.

HELIX.Context uses prepared functions to implement components, injection, binding, resources,
events, tickers, disposal, and lifecycle callbacks. These built-ins are useful examples because
they exercise validation, signature wiring, registration metadata, and multiple output targets.
