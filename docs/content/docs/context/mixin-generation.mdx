## Output directives

Outputs remain buffered until successful completion.

| Form | Destination |
|---|---|
| `@CODE text` / `@CODE<TARGET> text` | The expression attribute's single declared target. |
| `@CODE<Name> text` | Direct named injection target. |
| `@CODE<CLASS> text` | Generated partial class body. |
| `@CODE<FILE> text` | Generated file outside the class. |
| `@CODE<IMPLEMENTS> Type` | Generated base/interface list. |
| `@CODE<ANNOTATION> Type` | Generated type annotation. |
| `@USING Namespace;` | Generated using set. |
| `@MIXIN<Target><Priority> text` | Ordered contribution to a mixin method target. |

Every `@CODE` emits one output item; include required C# punctuation. `@MIXIN` is preferable for
ordered lifecycle contributions because it creates or contributes to a generated target.

```mixin
@USING System;
@CODE<IMPLEMENTS> IDisposable
@CODE<CLASS> private bool initialized;
@MIXIN<$Init><-100> initialized = true;
@MIXIN<$Dispose><100> initialized = false;
```

Mixin target and priority arguments may be dynamic. Missing priority is `0`; a dynamic priority
must resolve to an integer.

## Target syntax

| Syntax | Meaning |
|---|---|
| `Name` | Private instance target. |
| `^Name` | Public target. |
| `*Name` | Static target. |
| `^*Name` / `*^Name` | Public static target. |
| `~DelegateType` | Delegate signature reference. |
| `Name:DelegateType` | Named target backed by a delegate signature. |

`$` names are aliases defined by <FREntityCodeLink uid="MixinOn" /> or
<FREntityCodeLink uid="MixinDefineTargetAttribute" />. Component aliases include `$Init`,
`$LoadComponent`, `$LoadComponentLate`, `$Dispose`, and `$ConfigureComponent`.

`@RESOLVE_MIXIN<Local> target-expression` resolves a target's callable signature. `:wire` asks the
Roslyn expression context to produce compatible call arguments:

```mixin
@RESOLVE_MIXIN<Delegate> @local#Name
@ASSERT @local#Delegate:!?eq<null>
@MIXIN<(@local#Name)><(@attr#order)> @target:name(@local#Delegate:wire<(@target)>);
```

Use `:?signature<Method>` to require exact signature equality and `:?wireable<From><To>` to test
adaptability without generating arguments.

## Prepared global programs

Assembly-level <FREntityCodeLink uid="MixinPrepareGlobalAttribute" /> programs are parsed and
evaluated before target expressions. At top level they may initialize variables, declare
functions, and log preparation data. They cannot inspect `@this`, `@target`, or `@attr` during
initialization because there is no target context. Function bodies may reference them because the
body executes later in its caller's context.

```csharp
[assembly: MixinPrepareGlobal(@"
@VAR<FeatureEnabled> true
@FUNC<EmitFeature>
  @ASSERT @var#FeatureEnabled
  @CODE<IMPLEMENTS> IGeneratedFeature
@END
")]
```

HELIX.Context uses prepared functions for components, injection, binding, resources, event
handlers, tickers, and lifecycle callbacks. Keep custom helpers narrow; the consuming attribute
should still own target selection and ordering relevant to its behavior.

## Contribution ordering

Generated contributions are grouped by resolved target and sorted by numeric order, lowest first.
When contributions share an order, generator contribution kind and deterministic source order
decide the result. Within application code, prefer distinct orders when one contribution depends
on another rather than relying on equal-order details.

The generator can place the base target call between negative and non-negative contributions. This
makes negative order useful for pre-base work and zero/positive order useful for normal or
post-base work where the target shape supports a base implementation.

## Diagnostics

| Directive | Output |
|---|---|
| `@LOG text` | Interpolated generator log entry. |
| `@DUMP<STATE>` | Program counter, call depth, values, and operation counts. |
| `@DUMP<BUFFER>` | Buffered generated output. |
| `@DUMP<AST>` | Parsed programs and instructions. |

Syntax validation catches unknown directives, invalid argument counts, malformed references,
bad function/scope structure, duplicate functions, and non-terminal predicates. Evaluation adds
errors for missing symbols, invalid regexes, unresolved targets, invalid priorities, and signature
wiring failures.

`@ASSERT` produces a condition-oriented failure and should be used for ordinary attribute usage
rules. Use an interpolated `@FAIL message` when a multi-branch semantic condition needs a clearer
explanation.
