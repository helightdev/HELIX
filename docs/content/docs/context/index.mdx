Context is HELIX's application framework for components and services. It discovers generated
component registrations, builds dependency graphs, activates components inside managed scopes,
injects and publishes values, runs lifecycle methods, and tears scopes down deterministically.

Application code declares behavior with attributes. Mixin expressions translate those attributes
into registration metadata and generated lifecycle code, avoiding broad runtime reflection.

## Typical component

```csharp
using HELIX;
using HELIX.Context;

[Component(typeof(ApplicationScope), order: 10)]
public partial class WelcomeService {
  [Inject]
  public GameSettings settings;

  [Inject]
  public SessionService session;

  [EventHandler(EventPriority.Late)]
  private void OnSessionStarted(SessionStartedEvent evt) {
    session = evt.session;
  }

  [Ticker("5 seconds")]
  private void Refresh() {
    session.Refresh();
  }

  [AutoDispose]
  private IDisposable subscription;

  [MixinMethod]
  private void OnInit() {
    subscription = session.Subscribe();
  }
}
```

The generated implementation registers the component and its dependency/event metadata, injects
`settings`, contributes callbacks to lifecycle targets, schedules `Refresh`, tracks the event
registration, and disposes both generated registrations and the annotated field during unload.

## Context versus Compose context

Context is the application and scene service system. Compose context is tree-local reactive data
addressed by `ContextKey<T>` and observed by composition boundaries. A Compose boundary may use
both, but the two systems have different ownership, lookup, and update semantics.
