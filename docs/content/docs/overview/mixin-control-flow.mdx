## Scopes and branches

`@SCOPE` starts a branch and `@END` closes it. Scopes delimit matching and jump destinations. They
are not variable scopes, so locals remain visible afterward.

```mixin
@SCOPE<Optional>
  @MATCH @attr#required:?eq<false>
  @CODE<$Init> ResolveOptional();
@END
```

| Directive | Behavior |
|---|---|
| `@MATCH expression` | Continue on true. On false, jump to the next sibling scope. |
| `@MATCH<Label> expression` | On false jump directly to the named sibling scope. |
| `@ASSERT expression` | Fail with a description of the first false condition. |
| `@GOTO<Label>` | Enter the named sibling scope after its declaration line. |
| `@SKIP` | Jump to the next sibling scope. Fail if none exists. |
| `@RETURN` | Return from a function, or successfully finish the top-level program. |
| `@FAIL message` | Fail immediately with an optional interpolated message. |
| `@END` | Close a scope or function. |

Labels belong to their containing function or top-level program. Functions may reuse label names.
A failed match only rejects its branch. It does not fail the expression.

```mixin
@SCOPE<Addressables>
  @MATCH @attr#source:?eq<2>
  @CODE LoadAddressable();
  @GOTO<Done>
@SCOPE<Resources>
  @MATCH @attr#source:?eq<3>
  @CODE LoadResource();
  @GOTO<Done>
@END
@FAIL Unsupported source
@SCOPE<Done>
@END
```

## Locals and variables

```mixin
@LOCAL<Name> interpolated expression
@VAR<Flag> interpolated expression
```

Locals exist for one evaluation and are shared with called functions. Variables begin with the
prepared global state and persist between mixin expressions applied during generation of the same
type. Both are mutable within an evaluation.

Variable changes and all code outputs are transactional. They commit only if the expression
succeeds. A failed assertion, explicit failure, or evaluation error discards them. Locals never
persist to another execution.

`@PUT<Local><Key> value` and `@PUSH<Local> value` update a local immutable table. Missing or
non-table locals start as an empty table.

## Functions and parameters

```mixin
@FUNC<EmitAssignment>
  @CODE @param#left = @param#right;
  @RETURN
@END

@CALL<EmitAssignment> @table:put<left><field>:put<right><value>
```

`@CALL<Name>` accepts an optional interpolated operand which becomes `@param`. Nested calls save
and restore the caller's parameter. Functions share locals and variables with the caller.
`@RETURN` or reaching the function's `@END` returns to the caller.

Definitions are indexed and skipped during top-level execution. Prepared-global functions can be
called by later target expressions. A function can call another function, but nested definitions
and duplicate names in the same combined library are invalid.

## Matching patterns

Use sibling scopes for alternatives and return after a terminal choice:

```mixin
@SCOPE
  @MATCH @arg#0:?ref
  @CODE RegisterRef(@target:name);
  @RETURN
@SCOPE
  @MATCH @arg#0:?argument
  @CODE RegisterValue(@target:name);
  @RETURN
@END
@FAIL Event handlers require a value or ref argument
```

Use `@ASSERT` for a requirement where the failed condition is meaningful by itself. Use `@FAIL`
after alternatives when no single predicate accurately explains the unsupported combination.
