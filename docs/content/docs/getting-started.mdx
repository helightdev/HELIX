The intended Compose workflow starts with an annotated method. The source generator turns that
method into a reusable <FREntityCodeLink uid="Composable" />, assigns its composition identity,
and handles entering and leaving its generated composition scope.

## Packages

| Package | Description |
|---|---|
| `HELIX` | Shared primitives and runtime utilities |
| `HELIX.Compose` | Compose runtime, UI Toolkit components, theming, signals, and generator attributes |
| `HELIX.Context` | Components, scopes, dependency injection, mixins, and expression-driven generation |

Add the packages through **Window → Package Manager → + → Add package from Git URL**:

```text
https://github.com/helightdev/HELIX.git?path=src/HELIX/Assets/Plugins/HELIX
https://github.com/helightdev/HELIX.git?path=src/HELIX/Assets/Plugins/HELIX.Compose
https://github.com/helightdev/HELIX.git?path=src/HELIX/Assets/Plugins/HELIX.Context
```

The packages currently target Unity `6000.4` or later.

## Create a generated composition

Add <FREntitySymbolLink uid="CompositionAttribute" /> to a static method whose first parameter is
`ref Composition`. Prefix the implementation name with `_`. The generator exposes the public name
without that prefix.

```csharp
using HELIX.Compose;

public static partial class InventoryView {
  [Composition]
  private static void _Content(ref Composition cx, string title) {
    using (cx.Column()) {
      cx.Text(title);
      cx.Button(
        content: static (ref Composition inner) => inner.Text("Sort"),
        action: static _ => SortInventory()
      );
    }
  }

  private static void SortInventory() { }
}
```

The generated member is used as the composition entry point:

```csharp
InventoryView.Content(ref cx, "Inventory");
```

The generated wrapper does more than rename the method. It enters a stable composition ID, invokes
the implementation, and restores the parent ID in a `finally` block. Nested generated compositions
therefore keep independent identity without application code touching low-level authoring state.

## Mount the root once

A UI Toolkit tree still needs one retained host boundary. Put a
<FREntityCodeLink uid="CompositionBoundaryNode" /> in your custom element and point it at the
generated composition.

```csharp
using HELIX.Compose;
using UnityEngine.UIElements;

[UxmlElement]
public partial class InventoryPanel : VisualElement {
  public InventoryPanel() {
    Add(new CompositionBoundaryNode {
      composable = static (ref Composition cx) =>
        InventoryView.Content(ref cx, "Inventory")
    });
  }
}
```

This small host is the manual integration edge. Most UI work should live in generated composition
methods and generated boundary components.
