# Mixins
Mixins provide a way for code to be declared in a generic reuusable with the ability to access local resources in
a shared way without the annoying boilerplate. It combines advantages of abstract classes with the composability of
interfaces.

## Invocation Order
Lower order mixins get invoked before higher order mixins.
If both mixins share the same order, they are sorted as following:
- Locally declared methods in declaration order
- Type mixin contributed mixins in left-to-right order traversig the inheritance chain downwards (Dedupplicated)
- Type attribute contributed mixins in declaration order

## Generation
Mixins are generated for every type the is annotated with [EnableMixins] or has inherited type that does.

## Collection of Mixin Candidates
Method candidates are collected from 
- All declared methods in the compilation unit (the paritial class)
- All proxied methods in inherited IMixin implementing interfaces
- All proxied mixin methods from mixin annotation sources

## Mixin Method Inovcation
The generator generally only generates the glue bindings, value wiring and ordering for mixin methods.
A mixin can define the sources of the parameters using the [MixinInject]/[MixinInjectAttribute] attribute.
This attribute allows one to specify the source using the MixinInject enum. Following are support:
- This: The class instance
- Target: The mixin reference target
  * Method(string): Method Name
  * Class(string): Class Name
  * Class(any): Class Instance
  * Field(ref any): Reference to the field
  * Field(any): The value of the field
  * Property(ref any): The reference to a temporary variable with the value of the property. 
    After invocation, the value is assigned back to the property.
  * Property(any): The current value of the property
- Attribute: If injected using a mixin attribute, resolves to a constant wired value of the calling mixin attribute
- Delegate: If injected on a method, tries passing the method as a delegate reference into it.
- ReturnValue(ref): If injected on a method, passes in the current return value (or default) and lets the method modify it.
- Unmarked: Positional argument of the method. May have less arguments then the method, but never more.

Injected paramters that refer to named values try resolving using the parameter name ignoring casing.
If the `name` field of the inject attribute is not null, the name variable is used instead.

Mixins methods have to be declared either as void, or a boolean returning function.
If the function returns a boolean, true is interpreted as continue with false meaning "return"

## Mixin Targets
Mixins generally count on the target they are injected on not already existing. However following cases are still allowed:
- The target is declared but only as a partial method (visibility irrelevant but will be respected).
- The target is declared as abstract or virtual in a supertype - The implementation will be generated. For virtual,
  the base implementation will be called with priority 0 at position 0.
- Otherwise: Implementation will be generated by the generator with private visibility.

## MixinPropertyAttribute
This attribute instructs the generator to generate an implementation of the annotated attribute in the mixin interface
if it doesn't already have an implementation.

## MixinDeclareVariableAttribute
This attribute instructs the generator to generate a variable of the given type and name.
